# WordPress 插件清理工具 — WP Plugin Cleanup   

> 扫描并清理已卸载或停用插件遗留在 WordPress 数据库中的冗余数据，包括孤立选项、定时任务、自定义数据表、过期瞬态缓存和文章元数据，释放数据库空间，保持站点数据库整洁。
   

**版本**：v1.0.0  
**适配**：WordPress 5.8+  
**PHP**：≥ 7.2  
**作者**：softbangong  
**授权**：不限制网站数量，下载安装后永久免费使用   

## 插件简介   

![](https://www.softbangong.com/wp-content/uploads/2026/07/4111cd5c-2c3d-41c9-82af-e9d17573a288.png)   

当您在 WordPress 中安装、使用、然后卸载插件时，很多插件并不会彻底清理自己在数据库中写入的数据。久而久之，`wp_options` 表中会堆积大量孤立选项，`wp_cron` 中残留无效的定时任务，数据库中遗留不再使用的自定义数据表，以及过期的瞬态缓存和孤立文章元数据。   

本插件专门解决这一问题：自动扫描 WordPress 数据库中所有可能属于已移除插件的残留数据，按模块分类展示详细信息，让您在清理前充分了解每条数据的来源和风险等级，确认无误后一键删除。   

插件内置五组独立扫描模块，每项数据标注风险等级（安全 / 注意 / 危险）和疑似来源插件，所有清理操作记录到操作日志，支持按成功或失败筛选查看。界面支持中文、英文及自动检测三种语言模式。   

## 功能特性   

### 五大扫描模块，独立开关控制   

插件提供五组扫描模块，每组模块配有独立的滑动开关，您可以按需启用或禁用任意模块，扫描时仅处理已启用的模块：   

| 模块 | 扫描内容 | 风险等级 |
| --- | ---- | ---- |
| 孤立选项 | 扫描 `wp_options` 表中的插件残留选项，自动排除 WordPress 核心选项、活跃插件选项和当前主题选项 | 注意 |
| 孤立定时任务 | 检测回调函数已缺失但仍残留在 Cron 计划中的定时任务钩子 | 安全 |
| 孤立数据表 | 查找不属于 WordPress 核心且不匹配任何活跃插件的自定义数据库表，同时显示行数、数据大小和存储引擎 | 危险 |
| 过期瞬态缓存 | 查找已超过过期时间的 `_transient_` 和 `_site_transient_` 条目，支持常规和站点级瞬态 | 安全 |
| 过期瞬态缓存 | 查找已超过过期时间的 `_transient_` 和 `_site_transient_` 条目，支持常规和站点级瞬态 | 安全 |
   

### 智能插件归属推测   

每条扫描结果都会自动分析其名称前缀或钩子名称，与当前已安装的插件目录名进行匹配，推测该数据最可能来自哪个插件，并在扫描结果表格的「疑似插件」列中展示，帮助您快速判断数据来源。   

### 三级风险标识   

每个扫描项均标注风险等级，以不同颜色徽章区分：   

— **安全（绿色）**：过期瞬态缓存、无回调的定时任务，可放心删除；  
— **注意（黄色）**：孤立选项、孤立文章元数据，建议复查后删除；  
— **危险（红色）**：孤立数据表，执行 DROP TABLE 将永久丢失全部数据，需格外谨慎。   

### 先预览再清理，多重确认机制   

— 扫描结果以表格形式展示，列出每项数据的关键字段（如选项名称、值预览、行数、大小、过期时间等），一目了然；  
— 每个模块支持「全选」和「取消全选」快捷操作，也可逐项勾选需要清理的数据；  
— 点击「执行选中清理」后弹出确认对话框，防止误操作；  
— 当选中项包含数据表或文章元数据时，会额外弹出二次确认提醒；  
— 只有经过您明确确认的数据才会被删除，不做任何自动清理。   

### 完整操作日志   

每次清理操作都会记录到操作日志中，包含执行时间、操作类型、处理目标和成功或失败状态：   

— 日志以可折叠面板展示，默认收起不占用页面空间；  
— 支持按「全部」「成功」「失败」三个标签页筛选查看；  
— 日志条数上限可在设置中配置（默认 100 条），超出后自动移除旧记录；  
— 提供「清除日志」按钮一键清空所有记录。   

### 中英双语界面   

插件内置完整的中英文翻译对照表，通过 `gettext` 过滤器实现界面语言切换：   

— 支持中文、English、自动检测三种模式；  
— 自动检测模式下，根据 WordPress 站点语言自动匹配中文或英文；  
— 语言切换通过页面顶部工具栏的下拉选择框即时切换，无需刷新。   

### 安全设计   

— 所有删除操作必须经过用户勾选和二次确认，不做任何自动清理；  
— 选项扫描自动排除 WordPress 核心选项、活跃插件前缀匹配的选项、当前主题前缀匹配的选项以及自身插件选项；  
— 定时任务扫描自动排除 WordPress 核心 Cron 钩子（`wp_`、`recovery_mode_` 等）；  
— 数据表扫描仅在名称不匹配任何活跃插件 slug 时才标记为孤立；  
— 文章元数据扫描自动排除 `_wp_`、`_edit_`、`_thumbnail_id`、`_menu_item_` 等 WordPress 核心元数据键；  
— 卸载插件时自动清理自身配置数据，不留残留。   

## 使用说明   

### 第一步：安装插件   

将 `wp-plugin-cleanup` 文件夹上传至网站 `/wp-content/plugins/` 目录，进入 WordPress 后台「插件」页面，找到「WP Plugin Cleanup」并点击启用。   

### 第二步：配置扫描模块   

进入后台左侧菜单「插件清理」，在页面顶部的「扫描模块设置」卡片中：   

— 通过滑动开关启用或禁用您需要扫描的模块（默认全部启用）；  
— 点击「保存更改」使配置生效。   

### 第三步：执行扫描   

— 点击「一键扫描全部」按钮对所有已启用模块执行扫描；  
— 也可以在每个模块卡片的标题栏右侧点击「扫描」按钮单独扫描该模块；  
— 扫描过程中页面显示全屏加载遮罩，防止重复提交；  
— 扫描完成后自动刷新页面，各模块卡片展开显示扫描结果。   

### 第四步：审查结果   

— 查看每个模块卡片中的扫描结果表格，重点关注「疑似插件」列和「风险等级」列；  
— 使用「全选」或「取消全选」快捷链接批量操作，或逐项勾选需要清理的数据；  
— 对标记为「危险」的数据表，请务必在删除前确认该表确实不再需要。   

### 第五步：执行清理   

— 勾选完成后点击页面底部的红色「执行选中清理」按钮；  
— 在弹出的确认对话框中点击确定；  
— 如果选中项包含数据表，会弹出第二次确认对话框；  
— 如果选中项包含文章元数据，同样会弹出额外确认；  
— 清理完成后页面显示操作结果统计（成功 / 失败 / 跳过数量）。   

### 第六步：查看日志   

— 页面底部「操作日志」面板可展开查看所有清理记录；  
— 点击「成功」或「失败」标签筛选对应状态的日志条目；  
— 日志保留条数可在模块设置中调整，默认为 100 条。   

## 注意事项   

— 本插件仅清理数据库中的残留数据，不会修改任何插件文件或 WordPress 核心文件；  
— 清理操作不可撤销，执行前请务必仔细审查扫描结果；  
— 删除数据表（DROP TABLE）会永久丢失该表中的所有数据，请格外谨慎；  
— 如果某个插件只是暂时停用而非卸载，其产生的选项和数据表不会被标记为孤立（因为插件目录仍然存在）；  
— 建议在清理前备份数据库，以防误删重要数据；  
— 插件自身在卸载时会自动删除所有配置数据和日志记录，不会在数据库中留下残留。
